# سجل العمل: نظام الأدوار والصلاحيات

> **الغرض:** سجل حيّ مختصر لحفظ القرارات، وما تمت مراجعته، وما بقي، وما أُجّل؛ لتسهيل استئناف العمل دون إعادة الخطوات أو نسيان الالتزامات.
>
> **الحالة الحالية:** مسودة تأسيسية. لا يُعد أي بند «منجزًا» إلا بعد التحقق منه وتسجيل الدليل أو الاختبار المناسب.

## 1. الهدف المعتمد

بناء نظام صلاحيات آمن ومرن في SkillVLT، يمكن التحكم فيه من لوحة الإدارة، مع تعريف مركزي وثابت للصلاحيات التي تدعمها المنصة، وإمكانية توزيعها على الأدوار والمستخدمين، وتهيئة البنية للباقات المستقبلية.

## 2. المبادئ والقرارات المعتمدة

- الأدوار الأساسية: **مدير النظام، المستخدم، الزائر**. الزائر يمكن أن يكون حالة غير مسجل الدخول، وليس بالضرورة سجلًا في قاعدة البيانات.
- تعريف الصلاحيات ومعانيها يكون مركزيًا ومنضبطًا في الكود؛ أما منحها وتوزيعها فيكون قابلًا للإدارة من لوحة القيادة.
- يجب أن يتحقق الخادم من الصلاحيات في كل عملية محمية؛ إخفاء عناصر الواجهة وحده لا يوفر حماية.
- ملكية البيانات منفصلة عن صلاحية الوصول إلى الخدمة؛ لا تمنح صلاحية الخدمة حق الاطلاع على بيانات الآخرين.
- يمكن أن تحدد الباقة مجموعة الصلاحيات المتاحة للمستخدم، مع إمكانية منح أو حجب صلاحيات فردية وفق سياسة واضحة.
- نهيئ التصميم لاستيعاب الباقات والاشتراكات من الآن، لكن نؤجل الدفع والفوترة ودورة الاشتراك الكاملة إلى أن نحتاجها.
- الصلاحية في استخدام خدمة ما منفصلة عن حصص الاستخدام وحدوده؛ لا نضيف حدودًا عددية اعتباطية.
- حماية حسابات الإدارة، خصوصًا منع فقدان آخر منفذ إداري، مطلب أمني يجب دراسته وتغطيته بالاختبارات.
- لا يبدأ التنفيذ الواسع قبل اكتمال التدقيق الأولي وتوثيق الموجود والفجوات.

## 3. ترتيب التنفيذ المعتمد

1. تدقيق شامل للتفويض الحالي في مسارات الويب وAPI وعمليات Blueprint والتنفيذ وملكية البيانات.
2. بناء كتالوج مركزي للصلاحيات وربطه بالأدوار.
3. تمكين إدارة المستخدمين والأدوار والصلاحيات من لوحة القيادة.
4. فرض التفويض في الخادم وإضافة اختبارات منع تجاوز الصلاحيات.
5. تهيئة البنية للباقات والاشتراكات دون تنفيذ الفوترة الآن.
6. تشغيل مجموعة الاختبارات الكاملة على SQLite وMySQL، وعدم الدمج قبل نجاح كليهما.

## 4. سجل المراجعة

| المجال | الحالة | الملاحظات |
|---|---|---|
| مصادقة الويب وتسجيل الدخول والخروج | تمت مراجعة أولية | تم استكمال واجهة الدخول واستعادة كلمة المرور في PR #297؛ لا يعني ذلك اكتمال التفويض |
| حماية صفحات أدوات المعلم في الويب | تمت مراجعة أولية | المسارات التي جرى الاطلاع عليها تستخدم `auth`؛ يلزم التحقق من كل المسارات والعمليات |
| مصادقة API | تمت مراجعة أولية | مسارات API المحمية تستخدم `auth:sanctum` بحسب `routes/api.php` |
| ملكية التنفيذ وموارد Blueprint | غير مدقق بالكامل | يلزم تتبع السياسات والاستعلامات والمتصرفات والخدمات والاختبارات |
| الأدوار الحالية في قاعدة البيانات | غير مدقق | يلزم البحث عن أي تطبيق قائم قبل اقتراح بنية جديدة |
| لوحة إدارة المستخدمين والصلاحيات | غير مدقق | لا يُفترض وجودها أو غيابها قبل فحص المشروع كاملًا |
| التفويض على كل عمليات Blueprint ودورة حياتها | غير مدقق | يشمل الإنشاء، وإضافة المراجعات، والتجميد، والترقية، والتفعيل، والإهمال، والإيقاف والتنفيذ |
| التفويض في كل مسارات الويب وAPI | غير مدقق بالكامل | يجب جرد المسارات ثم ربط كل عملية بقاعدة السماح/المنع |
| الباقات والاشتراكات | مؤجل | تهيئة معمارية فقط بعد التدقيق؛ الدفع والفوترة لاحقًا |

## 5. ما يجب فحصه في المرحلة الأولى

- [ ] جرد كل مسارات الويب وAPI وتصنيفها: عام، زائر، مستخدم مصادق، مدير، أو صلاحية خاصة.
- [ ] فحص نموذج User والمخططات والترحيلات والميدلوير ومقدمي الخدمات وأي Policies أو Gates أو حزم صلاحيات.
- [ ] تتبع ملكية Blueprint والمراجعات والتنفيذ عبر طبقات HTTP والتطبيق والمجال والتخزين.
- [ ] فحص الاختبارات الحالية المتعلقة بالمصادقة والتفويض وعزل بيانات المستخدمين.
- [ ] تسجيل كل فجوة مع مسار الملف أو اسم الاختبار أو دليل واضح.
- [ ] التمييز بين خلل أمني، ونقص وظيفي، وقرار منتج لم يُحسم بعد.
- [ ] تقديم خلاصة تدقيق وخطة صغيرة للتغيير التالي قبل تعديل منطق الصلاحيات.

## 6. أشياء مؤجلة عمدًا

- نظام الدفع والفوترة وتجديد الاشتراكات.
- فرض حدود استهلاك شهرية أو عددية قبل تحديد حاجة المنتج.
- إضافة أدوار متخصصة أخرى قبل أن يثبت احتياجها.
- أي تغيير في الكود مبني على افتراضات لم يؤكدها التدقيق.

## 8. قواعد تحديث هذا السجل

- حدّث الحالة بعد كل خطوة مكتملة، ولا تسجل النجاح قبل التحقق.
- دوّن الملفات والاختبارات ذات الصلة عند وجود نتيجة قابلة للتحقق.
- سجّل أسباب التأجيل والقرارات المفتوحة حتى لا يعاد بحثها من الصفر.
- لا تعتبر بندًا مؤجلًا ملغيًا؛ يبقى مؤجلًا إلى أن يُحسم صراحة.
- عند بدء جلسة جديدة، ابدأ بقراءة هذا السجل وتحقق من حالة الفرع ونتائج CI الحالية قبل المتابعة.
