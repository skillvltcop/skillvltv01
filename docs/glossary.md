# Glossary — English terms explained in Arabic

| Term | الشرح بالعربية |
|---|---|
| API — Application Programming Interface | واجهة برمجية تسمح للتطبيقات بالتواصل عبر طلبات واستجابات محددة. |
| Authentication | المصادقة: التحقق من هوية المستخدم. لا تعني تلقائيًا امتلاكه صلاحية تنفيذ كل عملية. |
| Authorization | التفويض/التحكم في الصلاحيات: تحديد ما يجوز للمستخدم فعله أو قراءته بعد المصادقة. |
| Audit event / audit trail | حدث أو سجل تدقيق: أثر محفوظ يوضح من نفذ عملية حساسة، وعلى أي مورد، ولماذا. |
| Blueprint | تعريف قابل لإعادة الاستخدام يضم الاسم والنطاق والملكية والبيانات الوصفية وسجل المراجعات ودورة الحياة. |
| Blueprint aggregate | تجميع نطاقي: كائن رئيسي يضمن اتساق Blueprint ومراجعاته وقواعد انتقالاته. |
| Behavior | السلوك: الخطوات المنطقية التي ينفذها Blueprint لإنتاج نتيجة من مدخلات وسياق. |
| Behavior digest | بصمة رقمية لتعريف السلوك، تساعد على تحديد نسخة تعريف السلوك المخزنة. |
| Contract | عقد البيانات: قواعد تصف شكل المدخلات المقبولة وما يلزم التحقق منه قبل التنفيذ. |
| Context | السياق: معلومات إضافية تصاحب مدخلات التنفيذ وتتاح لخطوات السلوك عند الحاجة. |
| Current revision | المراجعة الحالية: المراجعة التي اختيرت لتكون النسخة النشطة المرجعية للتنفيذ. |
| Discovery | الاكتشاف: واجهة تعرض الموارد المؤهلة للاستخدام مع بيانات وصفية محدودة. |
| Domain layer | طبقة المجال: مكان قواعد العمل والكيانات والقيم التي يجب أن تبقى صحيحة بغض النظر عن الواجهة. |
| Execution | سجل تشغيل واحد لنسخة محددة من Blueprint ومدخلاتها وسياقها وحالتها ونتيجتها. |
| Execution engine | محرك التنفيذ: يتحقق من شروط التنفيذ ويشغل السلوك عبر runtime. |
| Execution status | حالة التنفيذ: pending أو running أو completed أو failed. |
| Frozen revision | مراجعة مجمدة: نسخة سلوك لا ينبغي تعديلها بعد تجميدها؛ التغييرات الجديدة تكون في مراجعة أحدث. |
| IDOR — Insecure Direct Object Reference | ثغرة الوصول المباشر غير الآمن إلى كائن: تغيير معرّف في الطلب للوصول إلى مورد لا يملكه المستخدم. |
| Lifecycle | دورة الحياة: الحالات التي يمر بها Blueprint مثل draft وactive وdeprecated وsunset. |
| Metadata | بيانات وصفية: معلومات تعريفية وتصنيفية وتوثيقية، وليست بالضرورة بيانات تنفيذ أو صلاحيات. |
| Middleware | وسيط HTTP ينفذ فحوصًا مشتركة قبل وصول الطلب إلى المتحكم، مثل التحقق من المصادقة أو ضبط اللغة. |
| Namespace | نطاق أسماء يجمع Blueprints ضمن مساحة تسمية لتجنب التصادم وتحديد مجالها. |
| Owner / ownership | المالك/الملكية: هوية المستخدم أو النظام الذي يملك المورد. الملكية تختلف عن الدور الإداري. |
| Permission | صلاحية مسماة تمنح قدرة محددة مثل قراءة تفاصيل خاصة أو إدارة مراجعات النظام. |
| Projection | إسقاط بيانات: اختيار مجموعة حقول محددة من كائن أكبر لتكوين استجابة API محدودة. |
| Public visibility | رؤية عامة وفق سياسة المنتج: في SkillVLT تعني أهلية المورد للاكتشاف والاستخدام من المستخدمين المصادقين عند استيفاء شروط النشر، لا كشف تعريفه التنفيذي الكامل. |
| Repository | مستودع بيانات نطاقي: واجهة/طبقة تقرأ الكيانات وتحفظها دون نشر تفاصيل قاعدة البيانات إلى المجال. |
| Revision | مراجعة/نسخة: إصدار من تعريف Blueprint، يرتبط بتاريخ نسخ متتابع. |
| Runtime | بيئة التشغيل: المكونات التي تفسر خطوات السلوك وتنفيذها. |
| Sanctum | مكون Laravel لإدارة المصادقة ورموز API والجلسات المتوافقة. |
| Super administrator / super_admin | المسؤول الأعلى: يستطيع إدارة الأدوار والصلاحيات؛ الاستثناءات الحساسة تبقى مبررة ومسجلة. |
| System-owned Blueprint | Blueprint مملوك للنظام وليس لحساب مستخدم عادي. |
| Teacher tool registry | سجل أدوات المعلم: قائمة أهلية تحدد slugs والنطاقات وواجهات العرض التي يسمح بتقديمها كأدوات معلم. |
| ULID | معرّف فريد قابل للترتيب زمنيًا، يستخدمه المشروع لهويات Blueprints والمراجعات والتنفيذ. |
| Value object | كائن قيمة: يمثل مفهومًا صغيرًا مضبوطًا مثل ID أو اسم أو رقم مراجعة. |
| Visibility policy | سياسة الرؤية المخزنة على المراجعة؛ لا تكفي وحدها لإتاحة المورد دون شروط الملكية والحالة والمراجعة الحالية المجمدة. |
| Vite | أداة تطوير وبناء لأصول الواجهة الأمامية مثل JavaScript وCSS. |
